`src/components/ui/GalleryStrip` — горизонтальная лента кадров разной ширины (макет Figma 373-10064, «1440/slider 2»: чередование wide=1100 / narrow=520, высота 680, gap 80, подписи). Отдельный компонент от карусельного [[landing-structure]] `Slider` (277-16699) — это другой дизайн. Стоит перед Terraces ([page.tsx](src/app/page.tsx), `galleryInteriors`, картинки `public/images/gallery-*.png`).

**Механика (выбор заказчика — «пин-скролл»):** десктоп — секция высотой `100vh + travel` (`travel = track.scrollWidth - innerWidth`), внутри `position: sticky; top:0; height:100vh; overflow:hidden`; лента сдвигается `translateX = -(progress*travel)`, где `progress = -section.top / travel`. **Колесо НЕ перехватывается** (никакого preventDefault) — просто маппим прогресс прохода секции в сдвиг. Трансформ кладётся в DOM по ref (без ре-рендера на кадр). Мобайл / `prefers-reduced-motion` → класс `.native`: обычный `overflow-x:auto` (см. `GalleryStrip.module.scss`).

**Ловушка 1 (была реальным багом):** измерять `track.scrollWidth` нужно ПОСЛЕ применения класса `.pinned`. Если мерить в том же эффекте, где `setPinned(true)`, класс ещё не закоммичен → берётся НАТИВНАЯ геометрия (gap/padding другие) → travel занижен, последний кадр не доезжает. Решение: два `useIsomorphicLayoutEffect` — первый решает режим (`setPinned`), второй (deps `[pinned]`) измеряет и вешает scroll-слушатель уже с правильной геометрией.

**Ловушка 2:** НЕ вешать `overflow-x: hidden` на html/body/main ради борьбы с горизонтальным переполнением — это ломает `position: sticky` внутри. На сайте есть пред-существующее ~20px горизонтальное переполнение от `vw`-единиц (включают ширину скроллбара), не от галереи. Чинить — `scrollbar-gutter: stable` на html, а не `overflow-x:hidden`.

**Родственник — `src/components/sections/Showcase`** (Residences + 2×FeatureScreen в ОДИН scroll-lock, заменил эти 3 блока в [page.tsx]; старые компоненты Residences/FeatureScreen теперь не используются). Вертикальный step-through пин: секция `height: calc(var(--steps)*100vh)`, sticky-стейдж 100vh, шаги стопкой `position:absolute`. **Полностью scrubbed по скроллу (не CSS-переходы по смене состояния — иначе резко/багованно, было жалобой).** На каждый rAF считаем для КАЖДОГО шага `--intro`/`--introText`/`--par` (по refs); значения непрерывны на стыке → бесшовно. **Картинки разворачиваются clip-«шторкой» СНИЗУ ВВЕРХ (`.unfold{clip-path: inset(calc((1 - var(--intro))*100%) 0 0 0)}`) + параллакс `--par`. ВАЖНО: opacity/fade заказчик ОТВЕРГ («появляются через opacity — неправильно, должно раскатываться снизу вверх»). Плавность даёт ДЕМПФИРОВАНИЕ прогресса (lerp `p += (target-p)*0.085` в rAF, wake на scroll, sleep когда settled — аналог GSAP `scrub:1`), а НЕ opacity и НЕ CSS-transition.** Активный шаг проявляется поверх предыдущего (он остаётся под ним, `intro=1`). ТЕКСТ — clip-маска снизу вверх по `--introText`; ВАЖНО: у пройденных шагов (i<active) `introText=0` (текст скрыт), иначе он перекрывается с текстом активного (был баг). ПЕРВЫЙ шаг ВСЕГДА отрисован (по просьбе): у него `--intro=1` (без разворота), только параллакс; развороты картинки и смена текста — только у шагов 1+. `--introText` первого = 1 пока он текущий, иначе 0 (чтобы не перекрывать активный). Счётчик/клики (active) гейтятся видимостью секции, но картинка первого нарисована и до входа. data-state (React) — для `pointer-events` (none на неактивных) и порядка. Первый шаг — при входе секции (`rect.top < vh*0.85`). Мобайл/reduced-motion → `.static` (`.static .unfold{clip-path:none}`). Тот же приём (clip + lerp-демпфирование) у Presentation, но направление СЛЕВА НАПРАВО (`inset(0 X% 0 0)`). [[reveal-component]], [[anim-reference-elyse]].

**`CountUp` (`src/components/ui/CountUp`)** — число 0→end. Когда оно внутри clip-шторки, IntersectionObserver на нём не сработает → есть проп `play` (контролируемый запуск из родителя, напр. `play={i===active}` в Showcase); без `play` — сам наблюдает ближайшую `<section>`.
